# 디자인 결정

## 무엇을 참고했나

[leerob.com](https://leerob.com)의 결을 따라갑니다. 핵심은 네 가지입니다.

1. 따뜻한 종이 톤 배경 (`#f7f7f4`), 다크는 `#1a1a18`
2. 본문이 **세리프** — leerob은 `Iowan Old Style / Palatino / Georgia` 스택을
   씁니다. 여기서도 같은 스택을 쓰고, 한글은 `Noto Serif KR` 로 떨어지게
   순서를 잡았습니다. 라틴 글자는 앞쪽 세리프가, 한글은 Noto Serif KR이
   각각 잡히는 식입니다.
3. 좁은 한 단 + 실선 구분. 카드·그림자·알약 배지 없음
4. 오른쪽에 **세로로 긴 그림 한 장**. 스크롤하면 따라옵니다(`position: sticky`)

테마는 `prefers-color-scheme` 로 **시스템 설정을 따라갑니다.** 토글 버튼은
없습니다.

## 값

`styles.css` 상단 `:root` 에 모여 있습니다.

| 토큰 | 라이트 | 다크 |
| --- | --- | --- |
| `--bg` | `#f7f7f4` | `#1a1a18` |
| `--text` | `#16161e` | `#eceae4` |
| `--text-dim` | `#4d4d55` | `#a8a69f` |
| `--text-faint` | `#86868d` | `#7c7a74` |
| `--rule` | `#e3e2dc` | `#2e2e2b` |
| `--link-underline` | `#c7c6be` | `#55534d` |

- 본문 18px / `line-height: 1.75`
- `--font-ui` (시스템 산세리프)는 메타 정보·꼬리말 같은 작은 글자에만 씁니다
- 폰트는 Google Fonts에서 Noto Serif KR만 받습니다. 라틴은 시스템 폰트라
  네트워크 요청이 없습니다

### 제목의 '저'만 굵고 '서'는 가늘게 보이던 문제

구글은 Noto Serif KR을 **글자마다 다른 서브셋 파일**로 쪼개 보냅니다.
`저`(U+C800)는 `…117.woff2`, `서`(U+C11C)는 `…118.woff2` — 서로 다른
요청입니다. 한쪽이 늦거나 실패하면 그 글자만 시스템 폰트로 떨어지는데,
macOS 기본 한글 세리프(AppleMyungjo)는 **볼드가 없고 크롬이 합성 볼드도
씌우지 않습니다.** 그래서 한 글자만 가늘게 보입니다. `앱`·`웹`은 두 글자가
같은 서브셋(114)이라 이 현상이 없었습니다.

`--font-serif` 의 한글 뒤에 **볼드를 가진** `"Apple SD Gothic Neo"`(macOS),
`"Malgun Gothic"`(Windows)을 세워 해결했습니다. 웹폰트가 도착하면 그게
이기므로 평소 화면은 그대로이고, 못 받은 동안에도 굵기가 갈리지 않습니다.

- `display=block` 으로 바꾸는 방법도 있지만 느린 회선에서 본문 한글이
  최대 3초간 안 보입니다. 글이 주인공인 페이지라 택하지 않았습니다
- **설치돼 있지 않은 이름(`"Nanum Myeongjo"` 등)은 넣지 마세요.** macOS가
  내려받을 수 있는 폰트로 취급해 한글 차례를 가로채고는 볼드 없이 그려서
  문제를 되살립니다 (실제로 겪었습니다)

## 레이아웃

`.page` 가 2열 그리드입니다.

```
.page { grid-template-columns: minmax(0, 1fr) 320px; }
.intro   → 1열 1행
.content → 1열 2행
.art     → 2열 1~2행, sticky
```

DOM 순서는 `intro → art → content` 입니다. 900px 이하에서 한 단으로 접히면
자연스럽게 **머리말 → 그림 → 본문** 순서가 됩니다. leerob의 모바일은 그림을
아래로 내리지만, 여기서는 그림이 이 사이트의 성격을 말해주는 요소라 본문
앞에 둡니다.

## 항목 추가하기

각 섹션에 주석을 달아 두었습니다. `li` 하나를 같은 모양으로 복사하면 됩니다.

**저서** — 제목 왼쪽, 메타 오른쪽, 행마다 실선:

```html
<li>
  <a href="..." target="_blank" rel="noopener noreferrer">제목</a>
  <span class="meta">출판사 · 연도</span>
</li>
```

**앱 / 웹 서비스** — 제목 + 상태 + 설명 한 문단:

```html
<li>
  <p class="block-head">
    <a href="...">이름</a>
    <span class="meta">테스트 중</span>
  </p>
  <p class="note">설명</p>
</li>
```

링크가 아직 없으면 `<a>` 대신 `<span class="name">이름</span>` 을 씁니다.

상태는 색 배지가 아니라 흐린 글자입니다 — 절판 / 테스트 중 / 기획 중처럼
그대로 적으면 됩니다.

섹션 자체를 늘릴 때는 `<section class="section">` 을 복사하세요. 위쪽 실선과
간격은 클래스가 알아서 붙입니다.

## 접근성 / 잔손질

- `word-break: keep-all` — **빼지 마세요.** 없으면 한글이 단어 중간에서
  끊깁니다("만듭니 / 다.")
- `prefers-reduced-motion: reduce` 에서 풍경 애니메이션이 모두 멈춥니다
- 링크 밑줄은 기본으로 켜 두고 호버에서 진해집니다. `text-underline-offset`
  으로 한글 받침과 겹치지 않게 띄웠습니다
- 파비콘은 `assets/favicon.svg` — 어두운 타일에 세리프 `ian`. 16px에서도
  읽히도록 글자를 최대한 키웠습니다. `assets/apple-touch-icon.png` 는 같은
  SVG를 180px로 렌더링한 것이라, 파비콘을 고치면 같이 다시 만들어야 합니다
  ([workflow.md](workflow.md) 참고)

## 꼬리말의 메일 주소

꼬리말은 **메일 주소 한 줄**입니다. 주소를 **HTML 소스에 두지 않습니다.**
꼬리말에는 빈 `<span id="mail">` 만 있고, 페이지 끝 스크립트가 실행 시점에 주소를 조립해 `mailto:` 링크로
바꿔 넣습니다. 주소를 긁어 가는 봇은 대부분 HTML만 내려받아 정규식으로
훑고 자바스크립트는 돌리지 않으므로, 그 부류에게는 아무것도 잡히지
않습니다.

**주소를 바꾸려면** 브라우저 콘솔에서 `btoa('새주소')` 를 돌려 나온
문자열을 `index.html` 스크립트의 `atob('…')` 안에 갈아 끼우세요.

**확인하는 법** — 서버가 주는 원문에는 흔적이 없고, 브라우저가 그린
화면에는 링크가 있어야 합니다.

```sh
curl -s https://ian-works.github.io/ | grep -i mailto   # 아무것도 안 나와야 정상
```

**한계를 알고 쓰세요.**

- 헤드리스 브라우저를 돌리는 수집기에는 그대로 보입니다. 사람이 읽을 수
  있는 것은 기계도 읽을 수 있습니다. 이건 **대량 수집의 비용을 올리는
  것**이지 차단이 아닙니다
- 그래서 진짜 방어선은 **버릴 수 있는 전용 주소**를 쓰는 것입니다. 스팸이
  붙으면 주소를 바꾸고 위 한 줄만 고치면 끝입니다
- 저장소가 공개라 **커밋 메시지·이슈·메모에 주소를 평문으로 적지 마세요.**
  거기서 새면 페이지에서 가린 의미가 없어집니다
- 자바스크립트를 끈 사람에게는 안내 문구만 보입니다. 꼬리말에 그것
  하나뿐이라 그 사람에게는 연락 경로가 없는 셈입니다
